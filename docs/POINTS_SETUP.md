# Запуск пойнтовой системы — пошагово

Всё, что нужно сделать, чтобы пойнты, ракета на пойнтах и лидерборд заработали
на продакшене. Контракт ракеты **менять не нужно** — он остаётся как есть.

---

## Шаг 1. Хранилище пойнтов (обязательно)

Без него всё работает, но пойнты живут в памяти и сбрасываются при каждом
редеплое — на дашборде висит жёлтое предупреждение.

1. Vercel → твой проект → **Storage** → **Create Database** → **Upstash for
   Redis** (есть бесплатный тариф) → **Create**.
2. Нажми **Connect Project** и выбери проект. Vercel сам добавит переменные
   `KV_REST_API_URL` и `KV_REST_API_TOKEN` во все окружения.
3. Проверь: Vercel → Settings → Environment Variables — обе переменные на месте.

> Не Vercel? Подойдёт любой Upstash-совместимый REST-эндпоинт. Заведи базу на
> [console.upstash.com](https://console.upstash.com), возьми оттуда
> `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` — код принимает и такие
> имена.

## Шаг 2. Свой Base RPC (настоятельно рекомендую)

Сервер читает Base, чтобы проверять запуски ракеты, депозиты в Earn и хеши
блоков для ракеты на пойнтах. Публичные эндпоинты режут по лимитам — под
нагрузкой раскрытие раунда начнёт тормозить.

1. Возьми бесплатный ключ на [Alchemy](https://alchemy.com),
   [QuickNode](https://quicknode.com) или [Ankr](https://ankr.com) — сеть **Base
   Mainnet**.
2. Добавь в Vercel переменную:
   ```
   POINTS_RPC_URL = https://base-mainnet.g.alchemy.com/v2/ТВОЙ_КЛЮЧ
   ```
   Это серверная переменная, `NEXT_PUBLIC_` к ней не добавляй.

Без неё всё тоже работает — код падает на публичные RPC как на подстраховку.

## Шаг 3. Пул пойнтов для ракеты

Это твой бюджет: **больше, чем в пуле, игра не выплатит никогда**. Проигрыши
игроков возвращаются в пул, выигрыши уходят из него.

1. Добавь в Vercel:
   ```
   POINTS_POOL = 5000000
   ```
   Пул засеется сам при первом обращении к ракете. 5 млн пойнтов ≈ 200 максимальных
   ставок по 25 000 при X10 — на старт хватает с запасом.
2. Сгенерируй админ-токен и добавь его тоже:
   ```bash
   openssl rand -hex 32
   ```
   ```
   POINTS_ADMIN_TOKEN = вывод_команды_выше
   ```
   Без этой переменной роут пополнения отвечает отказом на любой запрос — он не
   открывается «по умолчанию».

> Хочешь запустить пойнты без игры на них? Поставь `POINTS_POOL=0` — спины
> будут на паузе с понятной надписью, а начисление за swap/bridge/perps/ракету
> продолжит работать.

## Шаг 4. Сезон (опционально)

```
NEXT_PUBLIC_POINTS_SEASON = s1
```

Все ключи в базе неймспейснуты этим значением. Поменяешь на `s2` — сезон 1
уезжает в архив (не удаляется), лидерборд стартует с нуля.

## Шаг 5. Деплой и проверка

```bash
git checkout claude/points-system-222q8r
git pull
```
Смёржи ветку в `main` (или задеплой её как preview) и дождись сборки.

Дальше — проверка по порядку:

1. **Хранилище живое.** Открой `/points` с подключённым кошельком. Жёлтого
   предупреждения про память быть не должно.
2. **Пул на месте.**
   ```bash
   curl https://ТВОЙ-ДОМЕН/api/points/pool
   ```
   Должно вернуть `funded` и `balance` равные `POINTS_POOL`, `available` — столько
   же, `maxBet` > 0.
3. **Начисление работает.** Сделай маленький swap на `/swap` (хоть на $1).
   Через 10–30 секунд в правом нижнем углу появится тост `+N points`, а чип в
   навбаре обновится. Если тост не пришёл — LI.FI ещё не проиндексировал маршрут;
   клиент сам повторит попытку (6с → 18с → 45с → 2мин) и переживёт перезагрузку
   страницы.
4. **Ракета на пойнтах.** `/lottery` → вкладка **✨ Play with points** → ставь
   минимум 100 → **Launch**. Через ~4 секунды (2 блока Base) прилетит результат.
   Нажми **Verify this spin** — там номер блока, его хеш и roll: любой может
   пересчитать.
5. **Выбор награды.** Сделай реальный запуск за ETH (`Ξ Play with ETH`). Если
   выпал выигрыш — увидишь две кнопки: `💰 Claim … ETH` и
   `✨ Take … points instead (+25%)`. Вторая ничего не подписывает и газа не
   тратит.

## Шаг 6. Пополнение пула на ходу

```bash
curl -X POST https://ТВОЙ-ДОМЕН/api/points/pool \
  -H "authorization: Bearer $POINTS_ADMIN_TOKEN" \
  -H "content-type: application/json" \
  -d '{"amount": 5000000}'
```

Отрицательная сумма забирает из пула незарезервированные пойнты:

```bash
-d '{"amount": -1000000}'
```

Зарезервированное под незавершённые раунды забрать нельзя — роут ответит 422.

## Шаг 7. Что настроить под себя

| Что | Где | Сейчас |
| --- | --- | --- |
| Ставки за объём | `lib/points/config.ts` → `SOURCES` | swap 10, bridge 15, perps 5, earn 8, ракета 200 пойнтов за $1 |
| Пороги тиров и перки | `lib/points/config.ts` → `TIERS` | Cadet → Pilot (1k) → Captain (10k) → Commander (50k) → Astronaut (200k) → Legend (1M) |
| Каталог наград | `lib/points/config.ts` → `REWARDS` | приватная группа 1k, токен-пул 10k, бесплатные запуски 2.5k, рибейт 25k, whitelist 200k |
| Реферальные % | `lib/points/config.ts` → `REFERRAL_L1` / `REFERRAL_L2` | 10% и 3% |
| Лимиты ставки в ракете | `lib/points/config.ts` → `ROCKET_MIN_BET` / `ROCKET_MAX_BET` | 100 / 25 000 |
| Бонус за выбор пойнтов вместо ETH | `lib/points/config.ts` → `CONVERT_RATE` / `CONVERT_BONUS` | 200 пойнтов за $1, +25% |

Дашборд, таблица «How to earn» и страница `/docs` читают эти же значения, так
что правка в одном месте меняет и правила, и то, что видит игрок — разъехаться
они не могут.

**Шансы ракеты менять не стоит:** `ROCKET_TABLE` и `multiplierForRoll` — точная
копия таблицы из `KriptoNr1.sol`. Именно поэтому игра на пойнтах честно
называется «той же ракетой». Поменяешь — расхождение с контрактом, и обещание
станет неправдой.

## Что придётся делать руками

Система считает и ранжирует. Сама она **не выдаёт** награды из каталога:

- **Приватная группа** — завести Telegram-группу и выдавать инвайты. Кто прошёл
  порог, видно в лидерборде (`/api/points/leaderboard?limit=500`).
- **Еженедельный токен-пул** — решаешь сам, чем и сколько платить; доли считай
  по пойнтам за неделю.
- **Бесплатные запуски за пойнты** — на контракте это `freeCredits`, начисляются
  только владельцем через инвайты. Хочешь выдавать за пойнты — либо руками, либо
  отдельной задачей (в этой ветке не делал: контракт трогать было нельзя).
- **Рибейт комиссии** — возврат вне приложения.

## Честно о границах доверия

- **Начисление за объём** проверяется независимо: LI.FI status API, receipt из
  Base с разбором событий контракта, история филлов Hyperliquid. Клиент не может
  выпросить себе пойнты — он только присылает tx hash.
- **Ракета на пойнтах** использует хеш будущего блока Base: ни игрок, ни ты не
  знаете исход в момент ставки, и каждый раунд пересчитывается по публичным
  данным. Но сам реестр пойнтов — на твоём сервере. Пойнты это программа
  лояльности, а не он-чейн актив; в UI и в README это сказано прямо, обещать
  игрокам он-чейн-гарантии на пойнты нельзя.
- **Бесплатные запуски за ETH фармятся** одноразовыми кошельками — так было и до
  пойнтов (см. комментарий в контракте). Пойнты за запуск считаются от ставки,
  так что фарм даёт мало, но `promoPool` всё равно держи как маркетинговый
  бюджет.
